The Problem

AI sees everything.
That's the problem.

Today's browser agents send your entire screen — passwords, Aadhaar numbers, bank details, faces — to cloud AI servers. Every screenshot is a privacy liability.

visibility

Full Screen Exposure

Raw screenshots with all your personal data are transmitted to third-party AI providers with every single agent step.

person_off

No Consent Mechanism

Users have no control over what data leaves their device. No redaction, no filtering, no proof of what was sent.

dangerous

Runaway AI Actions

Agents can submit payments, delete accounts, or accept agreements without meaningful human authorization checkpoints.

💡 The core question: Can an AI agent complete a KYC form, book a ticket, or fill a government application — without ever seeing your real data?

Privacy Architecture

8 guarantees. Each traceable to code.

Not aspirational goals — architecturally enforced constraints. Each one names the specific file that implements it.

shield

Raw PII Never Leaves

privacyBoundary.js — allowlist sanitizer strips all forbidden fields. Adversarial pre-flight scan hard-aborts if anything unredacted is found in the outbound payload.

face_retouching_off

Faces Blacked Out

offscreen.js + redactor.js — YuNet ONNX detects faces, canvas renders solid #000 rectangles before any transmission.

key_off

Passwords Never Filled

fieldMatcher.js — explicit exclusion of type="password" fields. No code path exists to auto-fill passwords.

cloud_off

Fully Local = Zero Cloud

agentBackend.js — hard architectural refusal, not a soft preference. decideNextAction() refuses to run in Local mode.

gavel

Consequential Actions Gated

consequentialActionDetector.js — 9-step authorization protocol. Submit, pay, delete — all require explicit human approval.

verified

Cryptographic Proof

merkleProof.js — tile-hashed Merkle tree with downloadable, independently verifiable proof of redaction.

phishing

Anti-Phishing Gate

trustGate.js — domain look-alike detection (Levenshtein), cross-domain form-action blocking, sensitive field combination checks.

block

Prompt Injection Defense

promptBuilder.js — explicit trusted/untrusted boundary. Webpage content is passive data, never instructions. Hostile directives rejected.

Checksum-First Design

Wherever a standard checksum exists (Luhn, Verhoeff, mod-97), we validate it — not just regex matching. Reduces false positives to near-zero.

layers

Range Claim Tracker

When a checksum-validated detector claims a character range, loose pattern matchers (like PHONE) skip it — preventing duplicate labels on already-classified data.

psychology

ONNX NER Layer

Quantized transformer (29 MB) for entity types without checksums — names, organizations. Runs in the offscreen WASM worker, fully on-device.

08 / 15

End-to-End Flow

From task to completion — every step traced.

1. Task Submission

User types: "Complete this form using my stored profile" → auto-selects Complete Mode

2. Page Analysis

domExtractor runs: interactive elements, visible text, PII detection (regex + NER + Luhn), URL scanning

3. Screenshot Capture + Face Detection

chrome.tabs.captureVisibleTab() → offscreen YuNet ONNX → face bounding boxes returned

4. Local Redaction

redactor.js paints solid #000 rectangles over all PII + faces. Unredacted screenshot immediately discarded.

5. State Diff + Form Analysis

stateDiffEngine computes page changes. formAnalyzer calculates field completion and store matchability.

6. Backend Dispatch

agentBackend.js POSTs redacted screenshot + sanitized DOM to Express server. Zero raw values cross the boundary.

7. VLM Reasoning

promptBuilder constructs multimodal payload → Pixtral-12B returns JSON action → ActionValidator sanitizes + validates

8. Action Translation

fill_from_local: fieldMatcher → privateDataStore → type locally
ask_user: highlight field → spotlight guide → user types manually

9. Safety Check

consequentialActionDetector intercepts submit/pay → 9-step Human Authorization Gate → user confirms

10. Loop

Re-analyze page, repeat until done or max 25 steps. Every step redacted independently.

Innovation Highlight

Multi-agent debate.
Transparent disagreement.

The first browser agent where AI disagreement is visible and explainable, not hidden behind a single answer.

// Both reasoners run in parallel (Promise.allSettled)
const [local, cloud] = await Promise.allSettled([
  decideNextActionLocalLLM(payload), // Qwen2.5
  decideNextAction(payload)        // Pixtral-12B
]);

// Compare decisions
const agree = actionsRoughlyMatch(local, cloud);
const gap = Math.abs(local.confidence - cloud.confidence);

// Resolution tiers
if (agree)           → AGREE
if (gap < 5%)       → AUTO_RESOLVE
if (gap 5%–15%)     → SHOW_BOTH
if (gap > 15%)      → ASK_USER

✓ Transparency, not averaging

Both decisions, both confidence scores, and the disagreement gap are shown to the user — not silently averaged into one opaque answer.

✓ Graceful degradation

Promise.allSettled() — if local model or cloud backend fails, the surviving decision is used with a clear "degraded" flag. Never fails silently.

✓ Safety gates still apply

A disagreement never bypasses consequential-action confirmation, sensitive-field ask_user, or stale-target re-validation. Debate adds transparency, not autonomy.

Safety Stack

Five layers of defense.

gavel

Consequential Action Gate

9-step protocol: stop → re-observe → verify target → explain → ask → bind approval → re-verify → execute → invalidate. Covers submit, pay, delete, publish, book, approve.

phishing

Anti-Phishing Trust Gate

Four checks: cross-domain form action (BLOCK), non-HTTPS (WARN), look-alike domains using Levenshtein distance (BLOCK), 3+ sensitive field categories (BLOCK).

shield

Privacy Boundary Enforcer

Explicit allowlists for every data field crossing the network. History value neutralization. Adversarial pre-flight scan that hard-aborts if PII is found in outbound payload.

block

Prompt Injection Defense

Architectural boundary: webpage content is marked as UNTRUSTED DATA in the system prompt. Hostile directives ("ignore instructions", "reveal credentials") are explicitly rejected.

verified_user

Action Verification Loop

Post-execution verification: did the click land? Did the value actually appear? Stale-target prevention re-validates selectors before every action execution.

balance

Compliance Signals

Local pattern-matching for GDPR/CCPA/HIPAA signals: cookie consent, privacy policy links, data processing notices. Informational — not a legal verdict.
